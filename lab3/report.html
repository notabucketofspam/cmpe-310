Lab 3 Report

Concept

Here's the "high-level" overview for the program:
  1. Zero some buffers
    1. The user input #1
    2. The user input #2
    3. A buffer for the output number
    4. Another buffer to hold pocket change
  2. The User Input Part
    1. Says to you, "please give me a string"
    2. Read an input string from the user
      • Store it in RAM
    3. Says again, "Give me another string"
    4. Read that one, too
      • And also store it in RAM
  3. String lengths
    1. Iterate over input string #1 until we hit nil
      • Store that result in RAM
    2. do the same thing for input string # 2
      • Store that one in RAM, as well
    3. Compare the two lengths
      • Store the smaller length in RAM
  4. Hamming Distance
    1. Check to see if we have iterated enough times
      • rbx holds the total number of bytes (the shorter of the two input strings)
      • rcx holds the current byte index
      • if we have, indeed, done our due iterating diligence, then... jump to the end
    2. Read a byte from the first input string (which we saved in RAM)
      • We hold this in R8
    3. Read a byte from input string #2 (this one is also in RAM)
      • Stored in r9
    4. xorq these two bytes
      • The result goes into r9
    5. bsfr on r9 and store the result in r10
      • This is Bit scan forward quad; we need q because these registers are 64-bit.
      • At this point, r10 holds the position of the bit that we found, if any. If no bit is found, then the zero flag is set.
    6. If the zero flag is set, then that means that there are no 1's in this byte.
      • in that case, we need to increment the byte index counter (rcx) and jump back to the very top of the Hamming Distance loop.
    7. If the zero flag isn't set, then...
      • We increment our accumulator
      • btrq is bit test and reset quad; using r10, this'll reset the bit that we found in r9 (we don't care about the test result here)
      • Jump back to the top of the loop for scanning this specific byte
    8. At the end of it all, store the accumulated value in RAM
  5. Printing the result
    1. Read the value from RAM
    2. Divide it by ten, convert it to ascii, store it in an output buffer.
      • Do this several times.
    3. Do some more syscall things to print it out.
  6. Quit

Explain

  1. Is this optimal?
    1. Not really. Using popcount would have been faster.
    2. Also, I had to copy-paste the same syscall code at least a half-dozen times.
  2. How did I come up with this?
    1. I paid attention to the powerpoint slides.
